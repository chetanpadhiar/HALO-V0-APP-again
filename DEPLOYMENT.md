# HALO V0 — Render API + Google/Microsoft OAuth deployment

## Architecture

- Vercel: `frontend/` — static HALO V0 UI + `/api/*` reverse proxy
- Render: `halo-api` — Node API, sessions, OAuth callbacks, mailbox fetching, persistence
- Render: `halo-v0` — existing Python ML service
- Render Postgres: `halo-v0-db` — production persistence

The Vercel `/api/*` rewrite keeps the browser's API requests and OAuth session cookie on the same first-party site. This is intentional for Safari compatibility.

## 1. Deploy the API

Create a Render Blueprint from this repository's `render.yaml`.

The API service uses:

- Root Directory: `backend/api`
- Build: `npm install`
- Start: `npm start`
- Health: `/health`

The Blueprint creates a Render Postgres database and wires `DATABASE_URL` automatically.

## 2. Fill Render secrets

Set these on `halo-api`:

- `ALLOWED_ORIGIN=https://YOUR-VERCEL-DOMAIN`
- `FRONTEND_URL=https://YOUR-VERCEL-DOMAIN`
- `OAUTH_REDIRECT_BASE_URL=https://YOUR-VERCEL-DOMAIN/api`
- `GOOGLE_CLIENT_ID=...`
- `GOOGLE_CLIENT_SECRET=...`
- `MICROSOFT_CLIENT_ID=...`
- `MICROSOFT_CLIENT_SECRET=...`
- `MICROSOFT_TENANT=common`

`TOKEN_ENCRYPTION_KEY` is generated by Render. Do not rotate it after real OAuth tokens are stored unless you also implement key rotation/migration.

## 3. Google Cloud OAuth

Create an OAuth client of type **Web application**.

Authorized redirect URI:

`https://YOUR-VERCEL-DOMAIN/api/auth/google/callback`

Use Gmail read-only scope. For testing, add the Google accounts you will use as test users if Google's consent screen requires it.

## 4. Microsoft Entra

Register an application and add a **Web** redirect URI:

`https://YOUR-VERCEL-DOMAIN/api/auth/microsoft/callback`

Grant delegated `Mail.Read` plus OpenID identity scopes. Use `common` for the tenant if the app should accept both organizational and personal Microsoft accounts, subject to the app registration's supported account types.

## 5. Deploy Vercel

Deploy the `frontend/` directory as the Vercel project root.

The bundled `vercel.json` proxies:

`/api/*` -> `https://halo-api.onrender.com/*`

If Render gives the API a different hostname, change the destination in `frontend/vercel.json` before deploying.

## 6. Test in this exact order

1. Open the Vercel URL.
2. Choose Student.
3. Choose Google.
4. Complete Google consent.
5. Browser returns to `/` with a real HALO session cookie.
6. HALO calls `/api/me` and confirms the authenticated account.
7. Run the real inbox scan.
8. Confirm the API fetches Gmail messages and sends normalized messages to the existing ML service.
9. Repeat with Microsoft.
10. Test logout and confirm `/api/me` returns 401 afterward.
11. Test Demo Mode with the network disabled — it must still work.

## Important

Do not put `GOOGLE_CLIENT_SECRET`, `MICROSOFT_CLIENT_SECRET`, `DATABASE_URL`, or `TOKEN_ENCRYPTION_KEY` in the frontend or Vercel environment.
